# Интерактивный 3D-прототип

Это браузерный UX-прототип публичной части «Смотрителя». Он демонстрирует путь посетителя: поиск художника → виртуальная комната → перемещение → карточка работы → 2D-список.

Архитектура зала загружается из 3D-модели [`assets/rooms/gallery-room.glb`](assets/rooms/gallery-room.glb), а не рассчитывается из количества работ. Настроенные габариты интерактивного зала по основному контуру модели — **14,83 × 12,75 × 3,71 м** (длина × ширина × высота). В браузере модель комнаты остаётся неподвижной: посетитель перемещает только камеру, а картины закреплены на стенах.

Картины не встраиваются в GLB: это отдельные JPG-файлы, которые приложение подставляет в экспозицию. Для этой модели размечены 10 проверенных точек крепления на меше стен `Line029`; каждая выдерживает раму до 1,69 × 1,32 м. Поэтому текущие работы можно заменять без повторного экспорта архитектуры. Для быстрой загрузки у каждой картины есть три браузерные версии: полноразмерная для карточки, 1024 px для 3D-сцены и 320 px для списка работ. Исходные файлы пользователя не изменяются.

## Подготовка и замена модели комнаты

1. Экспортируйте архитектуру из 3ds Max в бинарный glTF (`.glb`) с масштабом **1 единица = 1 метр**. Сохраняйте габариты **14,83 × 12,75 × 3,71 м** и ориентацию текущего зала; текстуры комнаты лучше встроить в GLB, чтобы на статическом сайте не появились недостающие внешние файлы.
2. Замените файл строго по пути `prototype/assets/rooms/gallery-room.glb`. Имя и расширение важны, в том числе для GitHub Pages с чувствительностью к регистру.
3. Если новая модель отличается по размерам или ориентации, синхронно обновите `MODEL_ROOM` и `MODEL_ARTWORK_ANCHORS` в `prototype/gallery-config.js`, затем проверьте начальную точку посетителя. Камера, границы перемещения и места для картин используют эту конфигурацию, поэтому один лишь новый GLB в таком случае недостаточен. Новая точка крепления должна ссылаться на настоящий меш стены и быть проверена для максимального размера рамы.
4. После замены сделайте жёсткое обновление страницы (`Ctrl+F5`) или отключите кэш в DevTools. Ручная проверка загрузки и замены описана в `TESTING.md` (T11–T14).

Запуск без установки зависимостей (из корня проекта):

```powershell
node prototype/serve.js
```

Затем открыть `http://localhost:4173`.

Демонстрационный поиск: `Айтен`, `Шейдаева` или `Ayten Sheydayeva`.

Управление в зале: `↑`/`W` — шаг вперёд на 1 м, `↓`/`S` — назад, `←`/`A` и `→`/`D` — боковой шаг влево и вправо относительно взгляда. Мышью или пальцем можно осматриваться во все стороны, включая потолок и пол; `Q`/`E` поворачивают взгляд, `R`/`F` наклоняют его вверх и вниз с клавиатуры. Горизонтальный обзор полный — 360°, вертикальный обзор ограничен 80° в каждую сторону, чтобы камера не переворачивалась. При первом открытии зала браузер загружает закреплённые версии Three.js и загрузчика GLB из CDN.

## Публикация на GitHub Pages

В корне проекта есть workflow `.github/workflows/deploy-pages.yml`. Он публикует папку `prototype` как статический сайт после каждого push в ветку `main`.

Для первой публикации создайте пустой репозиторий на GitHub. В его настройках откройте **Settings → Pages** и выберите источник **GitHub Actions**. Затем из корня проекта выполните:

```powershell
git init -b main
git add .
git commit -m "feat: publish virtual gallery"
git remote add origin https://github.com/<логин>/<репозиторий>.git
git push -u origin main
```

Для обычного project site адрес будет `https://<логин>.github.io/<репозиторий>/`; если репозиторий называется `<логин>.github.io`, сайт откроется по адресу `https://<логин>.github.io/`.

Это всё ещё MVP без backend и админки: дальше нужны хранилище сканов, база данных, загрузка исходников и редактор экспозиции.
